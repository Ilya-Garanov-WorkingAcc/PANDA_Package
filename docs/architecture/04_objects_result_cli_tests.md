# Блок 4 — объекты, результат, CLI, тесты (черновик для согласования)

Дата: 01.10.2026. Статус: **обсуждение**. Принято ранее: блоки 1–3, MDAnalysis, ось в классе формы.

## 1. Каталог объектов

### Описание физики (пишет автор поры/формы)

| Объект | Что это | Какую информацию несёт |
|--------|---------|------------------------|
| `Pore` (напр. `SlitPore`) | конкретная пора | размеры (H, L, k), положения стенок, ось профиля; правило бинов (слои/кольца); перевод в безразмерные величины; список своих форм; рекомендуемое центрирование |
| `InterfaceShape` (напр. `SlitRoll`) | формулы одной формы, без состояния | имя; список параметров; режимы смачивания с диапазонами θ; система отсчёта формул; ось симметрии и способ её поиска; формулы: профиль, границы φ, (опц.) площадь, центр масс, градиент, 3D-проверка «внутри» |
| `Parameter` | описание одного параметра | имя, умолчание, границы, единицы, символ, описание |
| `SymmetryAxis` | ось формы | ориентация (горизонтальная/вертикальная), функция поиска |
| `Regime`, `Frame` | перечисления | смачивание / несмачивание; система поры / система жидкости |

### Рабочие объекты (создаёт пользователь или библиотека)

| Объект | Что это | Какую информацию несёт |
|--------|---------|------------------------|
| `InterfaceModel` | форма в конкретной поре — то, что фитируют | ссылка на пору и форму; набор параметров с текущими умолчаниями/границами; методы `profile()`, `area()`, `phi_limits()`, `fit()` |
| `ParameterSet` | набор параметров модели | все `Parameter` модели; умеет разделить на свободные/фиксированные, упаковать в вектор и обратно, перевести единицы |
| `Trajectory` | источник кадров | позиции, размеры ящика, время, топология для выборок (MDAnalysis или массивы numpy) |
| `Centering` | способ центрирования | часть по координате профиля (`pore`/`liquid`/`none`) + осевая часть (`axis`/`none`) |
| `DensityProfile` | один профиль | координата (центры и края бинов), плотность, разброс; система отсчёта, отражён ли; геометрия поры; N и V; число кадров, интервал времени; выборка, центрирование; версия PANDA |
| `ProfileSet` | профили по блокам | список `DensityProfile` + времена блоков; `.mean()`, `.std()`, `.sem()` |
| `FitSpec` | все настройки одного фита | optimize, fixed, bounds, initial; нормировка; функция ошибки; окно; число стартов; метод оптимизации; n_jobs |
| `FitResult` | итог одного фита | см. §2 |
| `FitResultSet` | итоги по блокам | список `FitResult`; среднее ± разброс по каждому параметру |
| `ShapeComparison` | итог перебора форм | таблица «форма → loss, допустимость, параметры», лучшая форма |

Связи: `Pore` —содержит реестр→ `InterfaceShape`; `Pore` + `InterfaceShape` → `InterfaceModel`;
`Trajectory` + `Pore` + `Centering` → `ProfileSet`; `InterfaceModel` + `DensityProfile` + `FitSpec` → `FitResult`.

## 2. FitResult

| Группа | Поля |
|--------|------|
| что фитировали | пора, форма, режим смачивания, система отсчёта |
| параметры | значения всех параметров (градусы, доли H); какие свободны, какие фиксированы; δ в нм; выведенное ρ_bulk (режим `mean`) или φ (режим `bulk`) |
| качество | loss; `success` + сообщение оптимизатора; число стартов и вычислений |
| флаги проверок | `feasible` (в границах существования), `at_bounds` (какие параметры у границы), `at_regime_boundary` (прижат к 90°), `warnings` |
| альтернативы | результат в другом режиме смачивания; таблица всех стартов |
| для графика | координата, данные, модельная кривая, остатки |
| воспроизводимость | `FitSpec`, метаданные профиля, версия PANDA |

Методы: `summary()` (таблица текстом), `to_dict()`, `to_json()`, `plot()` (нужен matplotlib).
`print(result)` даёт короткую сводку с флагами — чтобы «θ = 90.6° у границы» нельзя было не заметить.

Неопределённость: из блоков (`fit_blocks` → среднее ± стандартное отклонение/ошибка среднего).
Для L1 оценка по гессиану ненадёжна — не делаем.

## 3. Перебор форм (`--shape auto`)

`pore.fit_all(profile)` → `ShapeComparison`: фит каждой зарегистрированной формы, сортировка по loss,
недопустимые (вне границ существования) помечены. Слот `ShapeClassifier` (протокол) — для будущего
NN-классификатора; при его наличии `auto` сначала спрашивает его. Критерий «минимум площади» —
там, где площадь выведена.

## 4. CLI

```
panda shapes [--pore slit]              # поры, формы, их параметры, границы, режимы, ось
panda profile TRAJ TOP --pore slit --walls "resname GRA" --select "resname DECAN" \
      --center-by pore[+axis] --bins 200 --start 2ns --block 1ns -o profile.npz
panda fit profile.npz --shape roll|auto --optimize theta delta --fix phi=0.5 \
      [--bounds theta=100:180] [--rho-bulk 5.1] -o result.json
panda run config.toml                   # profile + fit одним прогоном
```

- Единая логика: подкоманда = этап конвейера; параметры модели везде задаются одинаково
  (`--optimize`, `--fix name=value`, `--bounds name=lo:hi`) и берутся из `ParameterSet` → новая форма или
  параметр появляются в CLI без правки CLI.
- `panda fit` принимает и `.csv` без метаданных — тогда геометрия задаётся флагами (`--H`, `--L`, `--k`).
- Вывод: сводка в терминал + `result.json`; `--plot fit.png` по желанию.
- CLI — тонкая обёртка: собирает `FitSpec` и вызывает те же функции, что и Python API.
- Реализация: typer.

## 5. Тесты

```
tests/
├─ README.md            # что проверяет каждый набор, входные данные, ожидаемый результат, допуск
├─ unit/                # параметры (pack/unpack, единицы, ошибки), центрирование, бины, PBC
├─ contract/            # автоматически для КАЖДОЙ зарегистрированной формы
├─ regression/          # совпадение с формулами старой PANDA (эталонные числа)
├─ synthetic/           # восстановление параметров
├─ md/                  # маленькие сохранённые профили реальных расчётов
└─ cli/                 # команды запускаются и дают тот же ответ, что API
```

| Набор | Сценарий | Критерий |
|-------|----------|----------|
| contract | ∫ρ dz = φ; 0 ≤ ρ ≤ 1; конечность внутри границ существования; центр масс согласован с профилем; 3D-проверка «внутри» даёт тот же профиль | ≤ 1e-6 (аналитика), ≤ 1 % (облако точек) |
| regression | профиль и границы φ = старый `alpha.py` на сетке l, θ, δ, φ | ≤ 1e-12 |
| unit/fitting | один оптимизатор при 1, 2, 3 свободных параметрах; фиксированные не меняются; ошибки при неверных именах и «не влияющих» параметрах | точное равенство / ожидаемое исключение |
| synthetic | θ=120°, δ=0.03 → профиль + шум → фит в режимах φ / (δ, φ) / (θ, δ, φ) | \|Δθ\| < 1°, \|Δδ\| < 0.005 |
| synthetic/centering | интерфейс смещён относительно центра поры; сравнение `pore` / `liquid` / `shift` | \|Δθ\| < 1° хотя бы для рекомендованного способа |
| synthetic/regime | θ=60° и θ=120° — выбран верный режим смачивания | режим верный, \|Δθ\| < 1° |
| md | графит и кальцит: θ в ожидаемом диапазоне, флаги проверок выставлены как надо | допуск по блокам |

Отдельно от pytest — `validation/`: скрипты, строящие графики для документации и статьи
(Δθ от уровня шума, от числа бинов, сравнение центрирований, истинный и восстановленный профиль).
Пороговые значения выше — стартовые, уточняются по первым прогонам.
