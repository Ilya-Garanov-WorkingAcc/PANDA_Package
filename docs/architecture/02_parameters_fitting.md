## 1. Описание параметра

```python
@dataclass(frozen=True)
class Parameter:
    name: str                      # "theta" — ключ в optimize/fixed/CLI
    default: float | None          # значение по умолчанию (пользовательские единицы); None — «взять из данных или задать»
    bounds: tuple[float, float]    # допустимые границы для фита (пользовательские единицы)
    unit: Unit = DIMENSIONLESS     # DEG, PORE_WIDTH (доли H), ...
    symbol: str = ""               # "θ" — для таблиц и графиков
    description: str = ""
```

Стандартные параметры — в `core/parameters.py` (общие для всех пор):

| Имя | Умолч. | Границы | Единицы (польз. → внутр.) | Смысл |
|-----|--------|---------|---------------------------|-------|
| `theta` | 120 | (0, 180) | градусы → радианы | контактный угол через анализируемую жидкость |
| `delta` | 0.0 | (0, 0.1) | доли H (в результате дублируется в нм) | толщина смачивающего слоя |
| `phi` | None | (0, 1) | — | объёмная доля анализируемой жидкости |

Форма объявляет, какие параметры использует (`parameters = (THETA, DELTA, PHI)`), и может добавить свои
(например, у будущей поры может появиться угол раскрытия). Параметры геометрии (H, L, k) — **не** параметры
модели: это свойства поры, они фиксированы.

Единицы: пользователь везде пишет θ в градусах, δ — в долях H; формулы получают радианы и безразмерные
величины. Перевод — только в `ParameterSet`, нигде больше.

## 2. Как определяется, что свободно, а что фиксировано

Вызов:
```python
model.fit(profile,
          optimize=["theta", "delta"],      # что подбираем
          fixed={"phi": 0.31},               # что фиксируем и чему равно
          bounds={"theta": (100, 180)},      # сузить границы на этот вызов
          initial={"theta": 150})            # подсказать старт (иначе сетка)
```

Правила (проверяются до старта, ошибки — с понятным текстом):

1. `optimize` не задан → берётся `model.default_optimize` (для щели — θ, δ, как в статье 2).
2. Каждый параметр формы оказывается **либо** свободным, **либо** фиксированным; одновременно в
   `optimize` и `fixed` — ошибка; неизвестное имя — ошибка со списком допустимых.
3. Значение фиксированного: `fixed` → значение, выведенное из данных (только φ, §4) → `default`;
   если ничего нет — ошибка «задай phi или освободи его».
4. Свободный параметр, который **не влияет** на профиль (layer и θ; droplet в системе жидкости и δ) —
   ошибка. Проверка численная (малое возмущение параметра в стартовой точке не меняет профиль), поэтому
   работает для любой будущей формы без ручных объявлений.
5. `bounds` из вызова пересекаются с границами параметра и с режимом смачивания (§3).

Внутри: `ParameterSet.resolve(...) → FreeSpec` с методами `pack(dict) → x` и `unpack(x) → dict`
(полный набор: свободные из `x` + фиксированные). Оптимизатор видит только вектор `x` и box-границы.

Три режима из ТЗ — это просто три вызова, без веток в коде:
```python
model.fit(p, optimize=["phi"],                   fixed={"theta": 180, "delta": 0})
model.fit(p, optimize=["delta", "phi"],          fixed={"theta": 180})
model.fit(p, optimize=["theta", "delta", "phi"])
```

## 3. Режимы смачивания в оптимизаторе

Если интервал θ пересекает 90° → он режется на подынтервалы режимов, объявленных формой
(`(0, 90−ε)`, `(90+ε, 180)`, ε = 0.5°). Фит запускается в каждом, лучший — основной результат,
остальные — в `result.alternatives`. Если форма объявила только один режим — второй не запускается,
а в результат пишется, что режим не поддержан формулами.

## 4. Нормировка: ρ_bulk и φ

Два режима `normalization`, выбираются автоматически, можно задать явно:

| Режим | Когда | Данные | Модель | φ по умолчанию |
|-------|-------|--------|--------|----------------|
| `"bulk"` | пользователь дал `rho_bulk` | ρ(z) / ρ_bulk | ρ_model(z) | оценивается из данных: ∫ρ/ρ_bulk dz/H |
| `"mean"` | `rho_bulk` не дан | ρ(z) / n̄, n̄ = N/V | ρ_model(z) / φ | нет: задать (известна из построения системы) или освободить |

В режиме `"mean"` ρ_bulk не нужен; в результате выводится ρ_bulk = n̄/φ (проверка физичности: должна быть
близка к плотности чистой жидкости). Основание: ∫ρ_model dz = φ для всех 6 форм (проверено, 1.0000).
**Нужно подтвердить синтетикой**, что φ определяется вместе с θ, δ (нет вырождения).

## 5. Ограничения существования (φ_min ≤ φ ≤ φ_max)

Они зависят от θ и δ, поэтому это не box-границы. Решение для 1.0 — **мягкий барьер**:

- допустимая точка: loss как обычно;
- недопустимая: `loss = L_max + C · (насколько вышли за φ_min/φ_max)` — большое значение, но с наклоном
  обратно в допустимую область (у L-BFGS-B и Powell есть куда идти; NaN не возникает никогда);
- недопустимые стартовые точки отбрасываются до запуска; если допустимых нет — ошибка с диапазонами;
- итог проверяется: `result.feasible`.

Если синтетика покажет проблемы у границы — включаем опцию репараметризации
φ = φ_min + t·(φ_max − φ_min), t ∈ [0, 1].

## 6. Оптимизатор

```
fit(model, profile, spec)
  ├─ проверки входа (окно не пусто, профиль конечен, параметры разрешены, параметры влияют)
  ├─ для каждого режима смачивания:
  │    ├─ стартовые точки: сетка n^k по свободным (n=5) или LHS при k > 3; + initial
  │    ├─ отбросить недопустимые
  │    ├─ локальная минимизация из каждой: Optimizer.minimize(objective, x0, box)
  │    └─ лучший
  └─ FitResult (+ alternatives по режимам, таблица всех стартов)
```

- Целевая функция: L1 (по умолчанию, как в статьях), L2 — опция; окно по умолчанию — вся пора.
- `Optimizer` — сменный объект: `ScipyLocal(method="L-BFGS-B")` по умолчанию (статья 2), `"Powell"`,
  `"Nelder-Mead"`; позже можно добавить глобальный (`differential_evolution`) без правки `fit`.
- Аналитический градиент используется, если форма его даёт; иначе — конечные разности.
- Параллельность: `n_jobs=1` по умолчанию, без пула процессов (сейчас пул создаётся всегда — ненадёжно
  в Jupyter/Windows). Распараллеливать выгоднее по блокам, чем по стартам.
- Все настройки собираются в `FitSpec` (dataclass) → сохраняются в результате → `panda fit` и конфиг CLI
  используют тот же объект.
