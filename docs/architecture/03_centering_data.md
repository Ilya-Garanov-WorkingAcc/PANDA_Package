## 1. Конвейер целиком

```
файлы МД (.xtc/.gro, .trr, LAMMPS ...)        массивы numpy (синтетика, тесты)
        │ trajectory/reader (MDAnalysis)              │ ArrayTrajectory
        └──────────────────┬──────────────────────────┘
                           ▼
 ① Trajectory         кадры: позиции, ящик, время      — единый интерфейс, дальше бэкенд не виден
 ② Selection          какие атомы считаем (строка выборки; атомы или центры молекул)
 ③ Pore reference     где стенки/ось поры в этом кадре (из чисел или из атомов подложки)
 ④ Centering          сдвиг кадра: к центру поры или к центру масс жидкости (с учётом PBC)
 ⑤ Coordinate+Bins    пора переводит позиции в координату профиля (z для щели, r для цилиндра)
                      и даёт объёмы бинов (слои / кольца)
 ⑥ Accumulate         гистограмма → плотность по кадрам → средние по блокам (потоково, без всей траектории в памяти)
                           ▼
 ⑦ ProfileSet         профили блоков + метаданные  →  .mean() → DensityProfile  →  model.fit()
```

Ответственность: ①② — `trajectory/`; ③⑤ — пора (`pores/<тип>/pore.py`); ④ — `core/centering.py`;
⑥⑦ — `core/profile.py` + `trajectory/density.py`. Ядро не знает, щель это или цилиндр.

## 2. Пора из данных (③)

Сейчас стенки и H считаются руками (на графите: `Z_TOP`, `Z_BOT`, `H = Lz + Z_BOT − Z_TOP`).
Предлагается:

```python
pore = SlitPore.from_trajectory(traj, walls="resname GRA", L_axis="x")
#   H  — расстояние между поверхностями стенок (с учётом PBC: стенка может быть одна, с образом сверху)
#   L  — длина ящика по L_axis, k — отношение второй стороны к первой (RectCell)
pore = SlitPore(H=8.27, L=17.27, k=0.30, walls=(2.93, 11.20))   # или всё руками
```

- Поверхность стенки — по центрам крайних атомов (как сейчас); опционально `wall_offset` (нм) — явный
  параметр, а не скрытая константа. Это ровно «чувствительность к эффективной ширине поры» из статьи 1.
- Стенки могут считаться покадрово (подложка дрейфует) или один раз (по первому кадру / среднему).
- `L_axis` нужен, потому что для roll важно, какая сторона ящика поперёк валика.

## 2a. Что такое δ

δ — толщина слоя у стенки, куда анализируемая жидкость не заходит, в долях ширины щели H (статья 2:
wetting layer thickness). Причины слоя: плёнка смачивающей жидкости на стенке и собственный размер
молекул (центры атомов не могут лежать на поверхности стенки). Анализируемой жидкости доступна щель
шириной H·(1 − 2δ): |z| < 0.5 − δ. В статье 1 δ = 0, и угол завышался; в статье 2 δ — второй подгоняемый
параметр (по статье, порядка 0.01). Пример пересчёта: δ = 0.03 при H = 8 нм — это 0.24 нм.

## 3. Центрирование (④)

Стратегия = объект с одним методом «какой сдвиг применить к кадру». Какие координаты сдвигать, знает пора
(щель — только z, цилиндр — x и y).

| Стратегия | Сдвиг | Нужно | Система отсчёта результата |
|-----------|-------|-------|----------------------------|
| `PoreCenter()` | середина между стенками → 0 | стенки (③) | `PORE` |
| `LiquidCenter(weights="mass"\|"none")` | центр масс выбранной жидкости → 0; среднее по окружности (PBC) | — | `LIQUID` |
| `NoCentering(frame=...)` | 0 | данные уже отцентрированы | указывает пользователь |

После сдвига позиции заворачиваются обратно в ящик (PBC). Центрирование всегда покадровое: центр масс
жидкости гуляет, и без этого профиль размывается.

**Осевое центрирование (добавлено 01.10 по замечанию).** Центрирование состоит из двух независимых частей:

| Часть | Вдоль чего | Варианты | На что влияет |
|-------|-----------|----------|---------------|
| по координате профиля | z (щель) | `pore` / `liquid` / `none` | на 1D-профиль и фит |
| осевая (в плоскости стенок) | поперёк оси симметрии формы | `axis` / `none` | на 2D-карты плотности, circle-fit, облака точек для классификатора, картинки; для пор с радиальным профилем — и на сам профиль |

**Ось объявляется в классе формы** (уточнено 01.10): есть ли ось, как она направлена и как её искать.

```python
class SlitRoll(PlanarShape):
    axis = SymmetryAxis(orientation="horizontal", locate=liquid_center)   # ось цилиндрического сегмента
class SlitDoughnut(AxisymmetricShape):
    axis = SymmetryAxis(orientation="vertical", locate=liquid_center)
class SlitPerforation(ComplementShape):
    axis = SymmetryAxis(orientation="vertical", locate=void_center)      # ось проходит через отверстие
class SlitDroplet(AxisymmetricShape):
    axis = None                                                            # осевого центрирования нет
```

| Форма | Ось | Как ищется |
|-------|-----|------------|
| roll | горизонтальная (ось цилиндрического сегмента) | направление — то, вдоль которого плотность в плоскости однородна (или задано явно); положение — центр жидкости поперёк оси |
| doughnut | вертикальная | центр жидкости по x, y |
| perforation | вертикальная | центр **пустоты**: жидкость занимает всё, кроме отверстия, поэтому её центр масс указывает в противоположную точку (сдвиг на полпериода) |
| droplet, worm, layer | не вводится (`axis = None`) | — |

`locate` — функция-искатель из `core/centering.py` (`liquid_center`, `void_center`) или своя; всё с учётом PBC
(среднее по окружности). Стратегия `AxisCenter` читает `shape.axis`: нет оси — явная ошибка, если осевое
центрирование запрошено, и ничего не делает в режиме «по рекомендации формы».
Запись: `Centering(profile="pore", lateral="axis")`, коротко `"pore+axis"`. Так как ось зависит от формы,
при осевом центрировании форма передаётся в построение профиля/карты: `density_profile(..., shape="roll")`.

**Ориентация.** Капля/червяк сидят на одной стенке — на нижней или верхней. В `PORE` профиль при
необходимости отражается z → −z (определяется по знаку первого момента среднего профиля),
в метаданных пишется `flipped=True`.

**Сдвиг как параметр фита.** Дополнительно у любой модели есть служебный параметр `shift` (доли H),
по умолчанию фиксирован в 0; `optimize=[..., "shift"]` — «досцентрировать фитом», если центр известен плохо.

**Как это стыкуется с моделью** (из блока 1): профиль несёт `frame`; форма знает, в какой системе
записаны её формулы, и свой центр масс; ядро сдвигает модель в систему данных. Поэтому любую форму можно
фитировать по данным в любой системе отсчёта.

**Что выбирается по умолчанию:** пользователь явно → рекомендация формы → рекомендация поры.
Физическая разница: в `PORE` у droplet/worm δ определяется (капля стоит на слое δ над стенкой),
в `LIQUID` — нет (блок 2, проверка «параметр влияет»). Поэтому предлагаю для щели `PORE`, если стенки
известны, иначе `LIQUID` с предупреждением про δ. Окончательно — по синтетическому тесту из ТЗ
(интерфейс специально смещён, сравниваем способы центрирования).

## 4. Бины и плотность (⑤⑥)

- Пора задаёт координату и объёмы: щель — слои `Lx·Ly·dz`, цилиндр — кольца `2πr·dr·Lz`.
- В `PORE` бины выравниваются по стенкам: края первого и последнего бина совпадают со стенками →
  безразмерная координата точно в [−0.5, 0.5], без «пустого окна» (дефект старой версии).
  В `LIQUID` — бины по всей длине ящика вдоль оси.
- Задаётся `bins=200` или `bin_width=0.05` (нм).
- Если ящик меняется (NPT), объём бина считается покадрово.
- `per="atom"` (по умолчанию) или `per="molecule"` (центры масс молекул — меньше молекулярной «ряби» у стенок).

## 5. Блоки и время

- Время — в пользовательских единицах: `start="2 ns"`, `stop=...`, `block="1 ns"`, `stride=1`.
  Никаких ручных расчётов чанков.
- Результат — `ProfileSet` (блоки × бины): `.mean()`, `.std()`, `.sem()`, время каждого блока,
  утилита статистической неэффективности (из старого `stat_ineff.py`) для выбора длины блока.
- Чтение потоковое: кадр → гистограмма → прибавить к блоку; память не зависит от длины траектории.

## 6. Что хранит профиль (⑦)

`DensityProfile`: координата (центры и края бинов, нм), ρ (нм⁻³), опц. std/sem, `frame`, `flipped`,
ось, снимок геометрии поры (H, L, k, стенки), **N** (число частиц в поре) и **V** (объём поры) — нужны для
нормировки `mean`, число кадров, интервал времени, выборка, стратегия центрирования, версия PANDA.
Сохранение: `.npz` (полностью) и `.csv` (с метаданными в заголовке) — это вход `panda fit`.

## 7. Проверки на этом участке

| Проверка | Реакция |
|----------|---------|
| выборка пустая | ошибка |
| часть выбранных атомов вне поры (в подложке) | предупреждение с долей — скорее всего, неверная выборка или стенки |
| стенки не найдены / H ≤ 0 / стенки вне ящика | ошибка |
| ящик не прямоугольный вдоль оси профиля | ошибка (для 1.0) |
| мало кадров в блоке, пустые бины | предупреждение |
| центр масс жидкости заметно гуляет между блоками | предупреждение (форма, возможно, не равновесна) |

## 8. API (как это выглядит у пользователя)

```python
import panda

traj = panda.load_trajectory("md.xtc", "md.gro")                   # нужен panda[md]
pore = panda.SlitPore.from_trajectory(traj, walls="resname GRA", L_axis="x")
profiles = panda.density_profile(traj, pore, select="resname DECAN",
                                 centering="pore", bins=200,
                                 start="2 ns", block="1 ns")
res = pore.interface("roll").fit(profiles.mean(), optimize=["theta", "delta"])
per_block = panda.fit_blocks(pore.interface("roll"), profiles)      # θ = mean ± std
```

Тот же путь с синтетикой: `panda.synthetic.points(pore.interface("roll"), theta=120, ...)` →
`ArrayTrajectory` → `density_profile(...)` → `fit` — это и есть сквозной тест из ТЗ
«форма → профиль → центрирование → фит → восстановленные параметры».
