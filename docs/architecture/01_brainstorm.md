## 0. Что мы строим (моё понимание — поправь, если не так)

**Цель.** Переписать PANDA как библиотеку для публикации (PyPI + CPC). Код старой PANDA — источник
формул и эталон для регрессии, а не основа архитектуры.

**Что говорит ТЗ (жёсткие требования):**

1. Два уровня, которые нельзя смешивать: **тип поры** (геометрия) → **формы интерфейса** (своя аналитика).
2. У формы: профиль плотности, площадь, параметры, границы существования, ограничения, геом. функции.
3. Пора знает свои формы; форма знает свою математику; общий код — загрузка, оптимизация, вывод.
4. Оптимизатор не привязан к числу параметров: `optimize=[...]`, `fixed={...}`; модель описывает параметры
   (значение, границы).
5. Центрирование — отдельный этап; пора/форма лишь *рекомендует* способ (`pore` / `liquid`).
   Конвейер: траектория → центрирование → профиль → фит.
6. API: `pore.interface("thread").fit(profile, optimize=..., fixed=...)`, `pore.available_interfaces()`.
7. Новая форма / новая пора — без правки ядра.
8. CLI (`panda profile`, `panda fit`, `--shape auto`), документированные тесты, синтетическая валидация,
   src-layout, CI, PyPI.
9. Прототип — **минимум на двух типах пор**.

**Мои допущения (надо подтвердить):**

- A1. Builder (сборка стартовых МД-систем, YAML/hydra) в релиз 1.0 **не входит**.
- A2. NN-классификатор (PANDA-NN, PointNet++) в 1.0 не входит; архитектура оставляет под него слот.
- A3. Обратная совместимость со старым API не нужна.
- A4. ~~Формул для треугольной/цилиндрической пор у нас нет~~ → **решено (01.10):** формулы будут
  предоставлены позже; архитектура обязана позволять добавлять новые поры без правки ядра (§3.6, §3.7).
- A5. **Решено (01.10):** фит работает и для смачивания (θ < 90°), и для несмачивания (θ > 90°);
  формулы в двух режимах разные; встроенные проверки обязательны (§4.1).

## 1. Наблюдения из статей и кода, которые определяют архитектуру

| # | Факт | Следствие для архитектуры |
|---|------|---------------------------|
| F1 | 4 модуля `alpha/theta/delta/pi` численно совпадают (Δ ≤ 1.5e-15) | Одна модель на форму; «режимы» = выбор свободных параметров |
| F2 | Профиль строится из полуширины сечения `y(z)` тремя способами: `πy²/l²` (droplet, doughnut), `2y/l` (worm, roll), `1−πy²/l²` (perforation); layer — ступенька | «Проекция сечения в 1D-профиль» — переиспользуемый кусок, не дублировать в каждой форме |
| F3 | **droplet и worm записаны в системе координат самой жидкости** (центр сферы/цилиндра или центр масс), δ в профиль не входит вообще, только в φ_max. Остальные формы — в системе центра поры | Разница «центр жидкости / центр поры» сидит *внутри* формул. Нужна явная система отсчёта (§4) |
| F4 | ∫ρ_model dz = φ для всех форм (проверено: 1.0000 на θ∈{120,150,179}, δ∈{0,0.05}) | Можно нормировать данные не на ρ_bulk, а на среднюю плотность — тогда ρ_bulk не нужен, а φ становится честно фитируемым (§3.4) |
| F5 | Границы существования φ_min(l,θ,δ), φ_max(l,θ,δ) зависят от других параметров | Это **не** box-bounds; оптимизатору нужен механизм ограничений (§3.3) |
| F6 | У layer профиль не зависит от θ; у droplet/worm в системе жидкости не зависит от δ | Форма объявляет, от каких параметров она *зависит*; фит неиспользуемого параметра — ошибка/предупреждение |
| F7 | Площади S для общего (θ, δ) не выведены (заглушки); есть для частных случаев и в RectCell (θ=π, k) | `area()` — необязательный метод; отсутствие — явная ошибка `NotDerived`, не `return NotImplementedError` |
| F8 | Статья 2: θ ∈ (π/2, π), δ ∈ (0, 0.1–0.5), L-BFGS-B, сетка старта 5×5, аналитический градиент | Дефолты фита; градиент — опциональная возможность формы |
| F9 | Статья 1: Nelder–Mead, L1; статья 2: L-BFGS-B. Вне границ модель даёт NaN → L-BFGS-B падает | Оптимизатор сменный; NaN наружу из модели не выходит |
| F10 | Графит: декан смачивает (θ<90°) → библиотека не применима «в лоб»; θ упирается в нижнюю границу молча; окно фита может оказаться пустым молча | Явная «анализируемая фаза» и конвенция угла; флаги `at_bounds`, проверки входа с ошибками |
| F11 | RectCell: основание L×kL — та же щель с параметром k | `k` — параметр геометрии `SlitPore`, а не новая пора |
| F12 | Профиль строится по всем 3 осям центрирования, но для 1D важна только ось профиля | Центрирование — операция вдоль одной оси (+ развёртка PBC) |
| F13 | Пора определяет, *какой* это профиль: щель → ρ(z) в слоях; цилиндр → скорее ρ(r) в кольцах | Гистограммирование (объёмы бинов, ось/радиус) — ответственность поры, а не ядра |

## 2. Слои и направление зависимостей

```
            ┌──────────── cli/ ─────────────┐   ← тонкая обёртка, ничего не считает сама
            │                                │
   trajectory/ (io)        plotting/    analysis/ (сравнение форм, фазовые диаграммы, блоки)
            │                  │             │
            └───────► pores/<тип>/ ◄─────────┘   ← физика: геометрия поры + аналитика форм
                         │
                         ▼
                      core/                       ← не знает ни одной поры и формы
   parameters · model(ABC) · pore(ABC) · profile · centering · fitting · result · registry
                         │
                      numpy, scipy
```

Правило: **стрелки только вниз**. `core` не импортирует `pores`. Формы не импортируют оптимизатор.
`trajectory` — единственное место, где есть MD-бэкенд (опциональная зависимость). Ядро работает на
`numpy`-массивах → синтетические тесты не требуют MDAnalysis/mdtraj.

## 3. Модель: пора ↔ форма ↔ параметры ↔ оптимизатор

### 3.1 Пять сущностей

| Сущность | Что это | Состояние | Пример |
|----------|---------|-----------|--------|
| `Pore` | Геометрия ограничивающего пространства: размеры, ось профиля, приведение к безразмерным, бины, реестр форм, рекомендуемое центрирование | экземпляр с размерами | `SlitPore(H=8.0, L=17.3, k=0.3)` |
| `InterfaceShape` | Чистая математика формы в безразмерных переменных; без состояния | класс | `SlitRoll` |
| `Parameter` | Описание одного параметра: имя, единицы, умолчание, границы, символ | неизменяемый | `theta: deg, 120, (90,180)` |
| `InterfaceModel` | **Связка** поры и формы + её набор параметров. Это то, что фитируют | экземпляр | `pore.interface("roll")` |
| `Fitter` (функция `fit`) | Общий оптимизатор: собирает вектор из свободных параметров | без состояния | `fit(model, profile, spec)` |

Почему нужна отдельная связка `InterfaceModel`: форма — чистые формулы, им нужна геометрия
(`l`, `k`), которая живёт в поре. Пользователь же хочет объект, у которого есть и `.fit()`, и
`.profile()`, и `.parameters`. Связка = «форма, подставленная в конкретную пору».

### 3.2 Контракт формы (минимальный)

```python
class InterfaceShape(ABC):
    name: ClassVar[str]                       # "roll"
    parameters: ClassVar[tuple[Parameter, ...]]   # от чего зависит: (theta, delta, phi)
    frame: ClassVar[Frame]                    # в какой системе записаны формулы: PORE или LIQUID

    # обязательное
    def profile(self, z, g, p) -> ndarray     # ρ/ρ_bulk в безразмерных z, в своей системе отсчёта
    def phi_limits(self, g, p) -> tuple[float, float]   # существование (общее: feasible(g, p))

    # необязательное (по умолчанию — честное NotDerived / численный расчёт)
    def area(self, g, p) -> float
    def center_of_mass(self, g, p) -> float  # по умолчанию — численно из profile()
    def gradient(self, z, g, p) -> dict[str, ndarray]
    def contains(self, xyz, g, p) -> bool[]  # 3D-индикатор → синтетика, builder, датасет для NN
```

`g` — безразмерная геометрия поры (`l`, `k`), `p` — параметры во внутренних единицах (θ в радианах).
Вспомогательные функции (`d_roll`, `r_droplet`, `y(z)`) — приватные методы/функции модуля формы.

**Переиспользование (F2):** миксины проекции, форма реализует только сечение:

```python
class AxisymmetricShape(InterfaceShape):   # ρ = π y(z)² / (k l²)
class PlanarShape(InterfaceShape):         # ρ = 2 y(z) / l
class ComplementShape(...)                 # ρ = 1 − π y(z)² / (k l²)  (perforation)
```

Добавить форму = один файл: сечение `y(z)`, размер, `phi_limits`, (опц.) площадь.

### 3.3 Параметры и их освобождение

```python
Parameter(name="theta", default=120.0, bounds=(90.0, 180.0), unit="deg", symbol="θ")
Parameter(name="delta", default=0.0,   bounds=(0.0, 0.1),   unit="H",   symbol="δ")
Parameter(name="phi",   default=None,  bounds=(0.0, 1.0),   unit="",    symbol="φ")   # None → из данных
```

`ParameterSet` (набор модели) умеет:
- `resolve(optimize, fixed, overrides)` → какие свободны, какие фиксированы, с проверками:
  неизвестное имя, параметр одновременно в `optimize` и `fixed`, свободный параметр, от которого форма не зависит (F6);
- `pack(dict) → x`, `unpack(x) → dict` только по свободным;
- перевод единиц (пользователь в градусах, формулы в радианах) — в одном месте.

**Ограничения, зависящие от других параметров (F5).** Варианты:

| Вариант | Как | + | − |
|---------|-----|---|---|
| a. Штраф | вне `phi_limits` целевая = большое конечное число | просто, любой оптимизатор | разрыв у границы, градиентные методы спотыкаются |
| b. Репараметризация | φ = φ_min + t·(φ_max − φ_min), t ∈ [0,1] — box | границы всегда прямоугольные | смысл t неочевиден; если φ фиксирован, ограничение ложится на θ, δ |
| c. scipy constraints | `NonlinearConstraint` + SLSQP/trust-constr | «правильно» | тяжело, медленнее, капризно |

**Рекомендую a** для 1.0: штраф + отбраковка недопустимых стартовых точек + флаг `feasible` в результате;
(b) — опцией, если синтетика покажет проблемы у границ.

Дефолт `optimize` задаёт модель (θ, δ — по статье 2); `fixed` перекрывает; φ без значения берётся из данных.

### 3.4 Нормировка профиля и роль φ (F4) — **важная развилка**

Сейчас: данные делятся на ρ_bulk, который пользователь задаёт руками (в ноутбуках — эвристики,
на графите я брал его из 2D-карты). Для любой формы, кроме layer, ρ_bulk из 1D-профиля напрямую не
читается.

Предложение: нормировать данные на **среднюю плотность** в поре `n̄ = N/V` (известна точно),
а модель — на φ:

  data:  ρ(z) / n̄        model:  ρ_model(z; θ, δ, φ) / φ      (обе интегрируются в 1)

Тогда ρ_bulk не нужен вообще, ρ_bulk = n̄/φ выводится, а «оптимизировать φ» из ТЗ получает
физический смысл: φ ↔ ρ_bulk при известном N. При фиксированном φ и известном ρ_bulk это ровно
старая постановка. Делаем `Normalization` стратегией: `"bulk"` (старое, нужен ρ_bulk) и `"mean"` (новое).
**Требует проверки** синтетикой: идентифицируемость φ вместе с θ, δ.

### 3.5 Расширение: как форма попадает в пору

| Вариант | Как добавить форму | Комментарий |
|---------|--------------------|-------------|
| a. Явный список в поре (как в ТЗ) | `SlitPore.shapes = [SlitDroplet, ..., NewShape]` | правка файла поры (ТЗ это допускает) |
| b. Регистрация декоратором | `@SlitPore.register` над классом формы | файл поры не трогаем; имя для CLI берётся из `name` |
| c. entry points | пакет-плагин объявляет `panda.shapes` в pyproject | сторонние формы без форка; для 1.0 избыточно |

**Рекомендую b** (+ c позже, механизм тот же реестр). Реестр также отдаёт имена для `--shape` в CLI.

### 3.6 Новая пора — что меняется

Новая пора = класс `Pore` с: размерами, `reduce()` (как перевести в безразмерные), `bin_volumes()`
(слои / кольца, F13), осью профиля, рекомендуемым центрированием, реестром форм. Ядро, фит, результат,
CLI, графики — те же. Проверка расширяемости: прототип второй поры должен иметь **другую координату профиля**
(иначе мы не проверим абстракцию по-настоящему).

### 3.7 Режимы смачивания (θ < 90° и θ > 90°)

Требование: один API для обоих случаев, формулы в режимах разные, встроенные проверки.

- Форма объявляет **режимы**: `regimes = {WETTING: (0°, 90°), NON_WETTING: (90°, 180°)}` и реализует
  формулы для каждого (`_profile_wetting`, `_profile_nonwetting` или общая с ветвлением — на усмотрение
  автора формы). Если какой-то режим не выведен — его просто нет в `regimes`, фит туда не пойдёт.
- θ = 90° — особая точка (tan θ, 1/cos θ в формулах) → вокруг неё зазор `ε` (по умолчанию 0.5°),
  значения там не считаются; если результат прижался к зазору — флаг `at_regime_boundary`.
- Если θ свободен и его диапазон пересекает 90°, фит **делится по режимам**: отдельный мультистарт в каждом,
  лучший по loss + оба результата в отчёте (видно, насколько уверенно выбран режим).
- Пользователь может сузить: `fixed_regime="wetting"` или `bounds={"theta": (100, 180)}`.

Встроенные проверки (до и после фита):

| Когда | Проверка | Реакция |
|-------|----------|---------|
| до | окно фита не пустое, в нём ≥ N точек | ошибка `EmptyWindow` (сейчас — тихо возвращается старт) |
| до | профиль конечен, ≥ 0, нормирован | ошибка |
| до | φ (если задан) допустим хоть при каком θ, δ в режиме | ошибка/предупреждение с диапазоном |
| до | свободный параметр влияет на профиль данной формы в данной системе отсчёта | ошибка «не определяется» |
| после | параметр у границы / у 90° | флаг `at_bounds` / `at_regime_boundary` |
| после | итог допустим (`phi_limits`) | флаг `feasible` |
| после | контраст loss между режимами | `regime_confidence` в результате |

### 3.8 Как добавляется новая пора (фундамент)

Новая пора — новая папка `pores/<имя>/`, ядро не меняется:

```python
# pores/cylinder/pore.py
class CylinderPore(Pore):
    name = "cylinder"
    coordinate = Radial()               # профиль ρ(r), бины — кольца (объём 2πr·dr·L)
    default_centering = AxisCenter()    # ось цилиндра
    def __init__(self, R, L): ...
    def geometry(self): return CylinderGeometry(l=self.L / self.R)   # безразмерные величины

# pores/cylinder/droplet.py
@CylinderPore.register
class CylinderDroplet(InterfaceShape):
    name = "droplet"
    parameters = (THETA, DELTA, PHI)
    regimes = {NON_WETTING: (90, 180)}
    def profile(self, r, g, p): ...
    def phi_limits(self, g, p): ...
```

Что пора обязана дать ядру (контракт `Pore`): координату профиля и объёмы бинов, перевод в безразмерные
величины, способ найти стенки/ось для центрирования, реестр форм. Всё остальное (параметры, фит,
проверки, результат, CLI, графики, синтетика, контрактные тесты) — общее.

## 4. Центрирование и системы отсчёта

ТЗ: центрирование — отдельный этап. Из кода (F3): формулы droplet/worm записаны в системе жидкости,
остальные — в системе поры. Поэтому одной стратегии на данных мало — нужна согласованная пара
«как сдвинули данные» ↔ «в какой системе считаем модель».

**Идея: у профиля и у модели есть явная система отсчёта (`Frame`).**

- `Frame.PORE` — 0 в центре поры (нужны положения стенок).
- `Frame.LIQUID` — 0 в центре масс анализируемой жидкости вдоль оси профиля.

Форма пишет формулы в удобной ей системе и сообщает `center_of_mass(g, p)` в системе поры
(для симметричных = 0; по умолчанию считается численно). Ядро переводит модель в систему данных:

  ρ_model^LIQUID(z) = ρ_model^PORE(z + z_cm(p))

→ любую форму можно фитить по любым данным, центрирование в формулах исчезает (флаг `center=True` уходит).

**Стратегии центрирования (на позициях, до гистограммы, покадрово):**

| Стратегия | Сдвиг | Нужно | Даёт `Frame` |
|-----------|-------|-------|--------------|
| `PoreCenter(walls=...)` | −(z_низ + z_верх)/2 | стенки: числа или выборка атомов подложки | PORE |
| `LiquidCenter()` | −circular_mean(z жидкости) с учётом PBC | — | LIQUID |
| `NoCentering()` | 0 | данные уже в нужной системе | указывает пользователь |

Плюс опция модели `shift` (свободный параметр z₀) — «центрирование фитом» для неуверенных случаев.
Пора задаёт `default_centering`, форма может переопределить (`droplet → LIQUID`). Ориентация
(капля на нижней или верхней стенке) — определяется по знаку первого момента профиля, z → −z.

Открытый момент: для `LIQUID` у droplet/worm δ не влияет на профиль (F3/F6) — значит δ из такого фита
не определяется. Это честно сообщать, а не молча возвращать стартовое значение.

## 5. Данные: от траектории к профилю

```
Trajectory (io)          → кадры: позиции выбранных атомов вдоль оси + длина ящика
   ↓ CenteringStrategy   → сдвиг на кадр (+ развёртка PBC)
   ↓ Pore.binning        → гистограмма с правильными объёмами бинов
   ↓ накопление, блоки   → DensityProfile (или ProfileSet по блокам)
```

- `DensityProfile` — данные + метаданные: `z` (нм), `rho` (нм⁻³), `frame`, `axis`, `n_frames`,
  `n_atoms`, `selection`, опц. `std`/`sem` по блокам. Сохранение в `.csv`/`.npz` (вход `panda fit density.csv`).
- Бэкенд траекторий один, опциональный (`pip install panda[md]`). Выбор: **MDAnalysis** (поддерживается
  активнее, язык выборок, много форматов) vs **mdtraj** (используется сейчас). Рекомендую MDAnalysis;
  слой `trajectory` изолирует выбор.
- Время/кадры задаются в пользовательских единицах (`start="2 ns"`, `block="1 ns"`), а не через ручной расчёт чанков.
- Выбор атомов — строкой выборки, никакого `assert residue in ["DECAN"]`.

## 6. Результат и анализ

`FitResult` (один фит): значения всех параметров (в пользовательских единицах) с пометкой свободный/фиксированный,
loss, `success`, `message`, `feasible`, `at_bounds` (графитовый случай θ = 90.6°), `identifiable`
(F6), число стартов/вычислений, таблица всех стартов, данные и модельная кривая, настройки, версия PANDA.
Методы: `summary()`, `to_dict()/to_json()`, `plot()` (через `plotting/`, опц. matplotlib).

Над этим (модуль `analysis/`):
- `fit_blocks(profiles)` → `FitResultSet` (mean ± std/sem по блокам, стат. неэффективность);
- `compare(results)` / `pore.fit_all(profile)` → таблица форм по loss + допустимость → `--shape auto`;
- `stability(pore, θ, δ)` → фазовая диаграмма по минимуму площади (где `area` выведена);
- слот `ShapeClassifier` (протокол) для внешнего NN-классификатора.

## 7. CLI

Одна логика: «что считаем» — подкоманда, «модель» — одинаковые флаги везде.

```
panda shapes [--pore slit]                          # поры, формы, параметры, дефолты, границы
panda profile TRAJ TOP --select "resname DECAN" --axis z \
      --walls "resname GRA" | --walls 2.93,11.20  --center-by pore|liquid \
      --bins 200 --start 2ns --block 1ns  -o profile.npz
panda fit profile.npz --pore slit --L 17.27 --shape roll|auto \
      --optimize theta delta --fix phi=0.5 [--theta 180] -o result.json
panda run config.toml                              # profile + fit одним прогоном (воспроизводимость)
```

Флаги модели генерируются из `ParameterSet` → новая форма/параметр появляется в CLI без правки CLI.
Реализация: **typer** (или click — уже в зависимостях). Склоняюсь к typer.

## 9. Подходы — сравнение

| | A. OOP: класс на форму, пора-реестр, общий fit | B. Функциональный: модули функций + словарь-спецификация | C. Геометрические примитивы: форма = сечение + проекция, всё остальное численно |
|---|---|---|---|
| Соответствие ТЗ | прямое (`TriangleDroplet(InterfaceShape)`) | частичное | прямое, но иначе |
| Добавить форму | 1 класс | 1 модуль + запись в словарь | 1 сечение |
| Проверяемость контракта | ABC + тесты контракта для всех зарегистрированных форм | слабая (опечатка в имени ключа) | сильная |
| Риск | низкий | низкий, но рассыпается при росте | высокий: численные площади/объёмы ≠ аналитика статей |
| Близость к существующим формулам | высокая | максимальная | низкая |

**Рекомендация: A** с элементом C — миксины проекций (сечение → профиль), остальная аналитика
в закрытой форме, как в статьях.

## 10. Тестирование, встроенное в архитектуру

- **Контрактные тесты** параметризуются реестром: каждая зарегистрированная форма автоматически проверяется
  на ∫ρ = φ, неотрицательность, ρ ≤ 1, конечность внутри `phi_limits`, согласованность `center_of_mass`,
  совпадение `contains()` с профилем (объём срезов). Новая форма получает тесты бесплатно.
- **Регрессия на старую PANDA**: фиксированные эталонные значения из `alpha.py` (сетка l, θ, δ, φ) —
  доказательство корректного переноса математики.
- **Синтетика** (ТЗ §12–13): форма → профиль (+ шум σ, разная дискретизация, смещение интерфейса) →
  центрирование → фит; режимы φ / (δ, φ) / (θ, δ, φ); критерии `|Δθ| < 1°` и т. п.; графики Δθ(σ).
- **MD**: маленькие сохранённые профили (графит, кальцит из статей) — `θ` в диапазоне, сравнение с circle-fit.
