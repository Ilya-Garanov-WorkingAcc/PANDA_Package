Проверки — скриптом в обсуждении от 15.10 (интеграл профиля, области существования по сетке θ, l, φ, δ).

## 1. Геометрия пор

| | Треугольная | Квадратная | Щель (для сравнения) |
|---|---|---|---|
| Сечение | равносторонний треугольник, сторона a | квадрат, сторона a | две плоские стенки, ширина H |
| Масштаб | a = 1 | a = 1 | H = 1 |
| Вдоль оси поры | длина l (в долях a), периодичность | то же | основание L × kL, l = L/H |
| Координата профиля | z — высота, перпендикулярно основанию | z — перпендикулярно стенке | z — поперёк щели |
| Начало z | центроид: основание −H′/3, вершина 2H′/3, H′ = √3·a′/2 | центр: ±a′/2 | центр: ±(1/2 − δ) |
| Слой δ | стенки сдвинуты внутрь на δ: a′ = 1 − 2√3·δ | a′ = 1 − 2δ | доступно 1 − 2δ |
| φ | относительно исходного сечения (√3/4 · l для треугольника, l для квадрата) | | относительно всей щели |
| Нормировка профиля | `ρ/ρ_bulk` = площадь сечения на высоте z / (l · ly), у «нитей» — ширина / ly | | πy²/l², 2y/l |
| Параметры формул | `(z, l, ly, φ, θ, δ)` | `(z, l, ly, φ, θ, δ)` | `(z, l, φ, θ, δ)` |

`ly` — ширина слоя, на которую нормируется профиль (ширина ящика поперёк профиля в долях a). Это параметр
бинов, а не физики: его даёт пора.

## 2. Формы

Имена: `<семейство>_w<N>c<M>` — касается N стенок, занимает M углов.
Семейства: `filament` (нить, однородна вдоль оси поры — профиль не зависит от l), `droplet` (капля),
`capsule` (капсула: цилиндр с полусферическими концами), `perforation` (плёнка с отверстием).

### Квадратная пора — 16 форм (профиль есть у всех)

| Форма | Условие существования | ∫ρ / (φ·A) | Замечание |
|-------|---|---|---|
| filament_w0c0, filament_w0c0_straight, filament_w1c0 | работает | 1.000 | |
| filament_w4c0, w4c1, w4c2, w4c3, w3c2, w2c0_opposite, w2c1 | **падает** (`UnboundLocalError`) | не проверено | в `cond_*` стоит `del l`, а ниже `l` используется |

| capsule_w4c4 | работает | 0.986 | расхождение 1.4 % — проверить формулу |
| perforation | работает | 1.000 при δ = 0; **0.74–0.87 при δ = 0.03** | профиль или условие неверно учитывают δ |

A — площадь исходного сечения (√3/4 для треугольника, 1 для квадрата). Проверка на тех точках сетки, где
`cond` = истина; θ ∈ {100, 120, 150, 170}°, δ ∈ {0, 0.03}.

## 3. Что из этого следует для архитектуры

| # | Наблюдение | Что меняется в спецификации |
|---|-----------|------------------------------|
| P1 | Существование задано **логическим условием** `cond(l, φ, θ, δ) → bool`, а не интервалом φ | обязательный метод формы — `feasible()`; `phi_limits()` — необязательный (есть у щели); если интервала нет, барьер плоский и по умолчанию берётся оптимизатор без производных |
| P2 | Устойчивость считается по **капиллярному функционалу** S_LV − cos θ · S_SL, а не по площади | форма отдаёт две площади: жидкость–жидкость и жидкость–стенка (`SurfaceTerms`); функционал считает ядро — одинаково для всех пор |
| P3 | У 10 из 14 форм треугольника профиля нет | `profile()` тоже необязательный: форма без профиля участвует в диаграмме устойчивости, но не в фите; `fit_all` её пропускает с пометкой |
| P4 | Профиль зависит от `ly` — ширины слоя нормировки | `ly` — свойство поры (из ящика), передаётся в геометрию формы; ядро о нём не знает |
| P5 | Треугольник несимметричен: z от основания до вершины, 0 — в центроиде | центр поры = центроид; `PoreCenter` для треугольника — свой способ (по основанию и вершине); ориентацию задаёт пора |
| P6 | δ у всех пор — сдвиг стенок внутрь, в долях характерного размера (H у щели, a у многоугольников) | единица `PORE_WIDTH` → `PORE_SIZE` («доли характерного размера поры») |
| P7 | Почти все формы существуют только при θ > 90° (θ < 90° — лишь формы, не зависящие от θ) | как и у щели: режим смачивания для многоугольников пока не объявлен (O1) |
| P8 | Проекция сечения: нити — ширина / ly, капли и капсулы — площадь / (l·ly) | те же миксины проекций, что у щели, с нормировкой из поры |
| P9 | Профили записаны в системе поры (капля стоит на нижней стенке) | `frame = PORE` для всех многоугольных форм |
| P10 | Функции векторизованы по (l, φ) — нужно для диаграмм устойчивости | `feasible` и `surface_terms` принимают массивы; фит вызывает их со скалярами |

## 4. Найденные расхождения — сообщить автору (Georgii, PANDA_Polygon)

1. Квадрат: 7 функций `cond_*` (`filament_w4c0`, `w4c1`, `w4c2`, `w4c3`, `w3c2`, `w2c0_opposite`, `w2c1`) падают
   с `UnboundLocalError`: `del l` в начале, затем `r_*(l, ...)`. На сайте эти формы, видимо, не отображаются.
2. Квадрат, `perforation`: при δ = 0.03 интеграл профиля 0.74–0.87 φ (при δ = 0 — точно φ).
3. Квадрат, `capsule_w4c4`: интеграл 0.986 φ при δ = 0 и 0.03.
4. Треугольник: профили есть только у 4 форм из 14 — остальные 10 нельзя фитировать.
5. Лицензия в репозитории не указана («terms will be added before a tagged release»).

## 5. Как это ложится в план

- Многоугольные поры переносятся **после** прототипа ядра на щели, но **до** CLI и релиза: это главная
  проверка того, что ядро не привязано к щели (заменяет «игрушечную» вторую пору из блока 4).
- Формулы переносятся как есть; эталон для регрессионных тестов — `PANDA_Polygon` на зафиксированном коммите.
- Формы с найденными расхождениями переносятся, но помечаются «не проверено» и не попадают в `fit_all`, пока
  автор не подтвердит исправление; контрактные тесты для них — с маркером `xfail` и ссылкой на пункт выше.
- Модели ещё меняются → перенос делаем последним из физических блоков; при обновлении `PANDA_Polygon` —
  поднимаем зафиксированный коммит и перегенерируем эталонные числа.
