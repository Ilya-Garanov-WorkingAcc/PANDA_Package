## 2. Физическая модель (как она реально устроена)

- **Пора одна — плоская щель.** Профиль ρ(z) поперёк щели, усреднённый по x, y.
- Безразмерные величины: `z/H ∈ [-0.5, 0.5]`, `ρ/ρ_bulk`, `l = L/H` (L — период вдоль направления искривления),
  `φ` — объёмная доля жидкости, θ — контактный угол (рад), δ — толщина исключённого слоя у каждой стенки
  в долях H (везде входит как `1 − 2δ`).
- **Формы:** droplet, doughnut, worm, roll, perforation, layer (в builder ещё AntiDroplet, AntiRoll).
- У каждой формы: характерный размер (`r_*` или `d_*`), `y_*(z)` (полуширина сечения),
  `rho_*(z)` (профиль), `phi_min_*`/`phi_max_*` (границы существования), `S_*` (площадь), частично `grad_*`.
- Профиль строится из `y(z)` двумя способами: «3D» формы (droplet, doughnut, perforation) — `π y²/l²`,
  «2D» (worm, roll) — `2y/l`, layer — ступенька. Это естественная точка разделения общего/частного.

### Ключевой результат: 4 модуля = 1 модель

Численно проверено (`smoke/phase1_reduction_check.py`, l = 1.94, θ ∈ {100, 120, 150, 179.9}°,
δ ∈ {0, 0.05, 0.1}, допустимые φ): для **всех 6 форм**

- `theta` ≡ `alpha(δ=0)`, `delta` ≡ `alpha(θ=π)`, `pi` ≡ `alpha(θ=π, δ=0)`;
- max |Δρ| ≤ 1.5·10⁻¹⁵, max |Δφ_min/max| ≤ 3.2·10⁻¹⁵, расхождений NaN нет.

**Следствие для архитектуры:** режимы `extention="theta"/"delta"/"alpha"/"pi"` — это не разные модели,
а разные наборы фиксированных параметров одной модели. Это ровно то, что PDF просит сделать
через `optimize=[...]`, `fixed={...}`. Четыре модуля сворачиваются в один класс на форму;
~770 строк дубликатов уходят.

Оговорка: проверена одна l; при переносе прогнать ту же проверку на сетке l.

### Чего не хватает в аналитике

- **Площадь `S_*` для общего случая (θ, δ) отсутствует** — в `alpha.py` все `S_*` возвращают заглушку.
  Есть только в частных случаях (theta, delta, pi). Нужно для сравнения форм по энергии и для фазовой
  диаграммы → вывести (Wolfram-ноутбуки в `origin/Dev:wolfram/`) или честно ограничить.
- Градиенты есть только для roll (`grad_rho_roll_alpha`); остальные — заглушки. Оптимизатор их всё равно
  не использует (`minimize` вызывается без `jac`).
- `rho_droplet_pi`: в коде комментарий «Equation from article (incorrect)» — формула в статье
  2025 г. и в коде различаются; сверить.

## 3. Параметры и оптимизация — как сейчас

| Режим | Свободные | Фиксированы | Границы в фите | Старт |
| --- | --- | --- | --- | --- |
| `alpha` | θ, δ | l, φ | θ ∈ [π/2+0.01, π], δ ∈ [0, 0.49] | сетка `samples×samples` |
| `theta` | θ | l, φ, (δ=0) | θ ∈ [π/2+0.01, π] | `samples` точек |
| `delta` | δ | l, φ, (θ=π) | δ ∈ [0, 0.49] | `samples` точек |

- **φ никогда не оптимизируется**: передаётся пользователем (в ноутбуках — считается как ∫ρ/ρ_bulk dz/H).
  В PDF φ фигурирует как свободный параметр — это новое требование, не перенос.
- **θ < 90° не поддерживается фитом** (нижняя граница π/2), хотя формулы `phi_max_*` имеют ветки для θ < π/2.
  Для гидрофильных систем нужно расширять — проверить корректность формул при θ < π/2.
- Выбор режима — строкой: `getattr(interface, f"rho_{type}_{extention}")` + `if/elif` по `extention`
  в трёх местах (сборка x0, bounds, распаковка `res.x`). Добавить режим = править 3 ветки.
- Целевая функция L1 (сумма |Δρ|), метод по умолчанию L-BFGS-B; фит только на `z/H ∈ (-0.5, 0.5)`.
- Всегда `ProcessPoolExecutor`, даже при `n_jobs=1` (в ноутбуке пользователя — ненадёжно на Windows/Jupyter).
- Вне (φ_min, φ_max) модель даёт NaN → L-BFGS-B может упасть (зафиксировано в ноутбуке пользователя,
  там заменено на Nelder-Mead). Границы существования **в фите не проверяются**.
- Результат — `dict` с разным набором ключей в зависимости от режима.

## 4. Центрирование — как сейчас

- В библиотеке: **только центр масс жидкости с учётом PBC** (среднее по окружности, `utils.get_center_pbc`),
  сдвиг по всем трём осям, жёстко внутри `get_density_profile`. Опции «центр поры» нет.
- `center_by="liquid"/"pore"` из PDF **в коде не существует** (ни в библиотеке, ни в ноутбуках) — это
  целевое требование.
- Дополнительно центрирование **зашито в аналитику**: `rho_droplet_*`/`rho_worm_*` имеют флаг
  `center=True`, сдвигающий профиль на центр тяжести сегмента (`z_dc`, `z_wc`). Симметричные формы
  (roll, doughnut, perforation, layer) центрированы по центру поры по построению.
  → Именно то смешение «центрирование ↔ аналитика», которое PDF просит разделить.
- В ноутбуках центрирование пишется заново каждый раз (`center_residue`, `z_wall` из максимума z подложки,
  `axis − H/2`).

## 5. Извлечение профиля — как сейчас

- `get_density_profile`: mdtraj `iterload` по чанкам, **только остаток `DECAN`** (assert), ось только Z,
  бины по всей высоте ящика (включая подложку), нормировка на Lx·Ly·dz.
- Пользователь вычисляет время/кадры вручную (`time`, `timestep`, `chunk_length`) — хрупко.
- ρ_bulk задаётся руками; в ноутбуках — эвристики (медиана на плато).
- Ноутбуки используют MDAnalysis, библиотека — mdtraj.

## 6. Что универсально, что специфично

**Универсальное (→ `core/`):** чтение траектории, выбор остатка, PBC-центрирование, гистограмма ρ(z),
блочное усреднение, оценка ρ_bulk и φ, нормировка (z/H, ρ/ρ_bulk), целевая функция, мультистарт,
оптимизатор с bounds, проверка границ существования, объект результата, статистическая неэффективность.

**Специфичное для формы:** `r/d(l, φ, θ, δ)`, `y(z)`, способ «y → ρ» (3D / 2D / ступенька),
`phi_min/phi_max`, `S`, собственный сдвиг центра (droplet, worm).

**Специфичное для поры (сейчас неявно):** безразмерная геометрия (`H`, `l`), ось профиля, набор форм,
смысл δ (слой у стенки).

## 7. Дефекты, найденные при аудите

1. `interface.pi` — это `numpy.pi` (float), а не подмодуль: `interface/__init__.py` делает
   `from .alpha import *`, импортирующий `pi` из numpy. Подмодуль достижим только через `importlib`.
2. `return NotImplementedError` вместо `raise` во всех заглушках `S_*_alpha`, `grad_*` — возвращается класс,
   ошибка молча проходит дальше.
3. `grad_rho_worm_theta`, `grad_rho_perforation_theta` в `alpha.py` — неверный суффикс.
4. Три модуля не импортируются (ImportError, см. §1).
5. `assert residue in ["DECAN"]` — анализ любой другой жидкости невозможен без правки кода.
6. `OptimizeWarning: Unknown solver options: disp` (scipy 1.18.1).
7. Мусорные файлы: `panda/#angle_blocks.py#`, `panda/geom/Roll copy.py`.
8. `setup.py`: `"Development Status :: 1 - Beta"` — недопустимый классификатор (правильно `4 - Beta`), PyPI его отклонит.

## 8. Существующие альтернативные методы (ценно для валидации)

В ноутбуках пользователя (`angle_approx.ipynb`, `theta_contact_angle.ipynb`, `theta_vs_temperature_1.ipynb`)
реализован **независимый метод**: 2D-карта плотности → изолиния ρ = ρ_bulk/2 → фит окружностей (Taubin SVD)
→ угол на уровне стенки. Это эталон для перекрёстной проверки θ из 1D-фита на реальных данных (Фаза 5).

## 10. Статья `25_MS_RectCellInterfaceShape.pdf` (кандидат на вторую пору)

Shistko S., Semenchuk A., Bakulin I., Gerke K., Kondratyuk N., Kopanichuk I. «Characterisation of the
dominant liquid-liquid interface shape in confined systems during molecular simulations».
*Molecular Simulation*, 2025. DOI 10.1080/08927022.2025.2574643. Та же группа, что и PANDA.

**Вывод: второго типа поры статья не даёт.** Это та же плоская щель, но с прямоугольным основанием
ячейки `L × kL` (0 < k ≤ 1, «squeeze parameter») вместо квадратного. Формы те же шесть.

Что даёт:

- Формулы ρ(z), площади S и границ существования всех 6 форм как функции (φ, k, l) — **только θ = π, δ = 0**
  (смачивающий слой явно не учитывается).
- При k = 1 совпадает с текущей моделью (проверено для roll: `d = φl − π/4`, `ρ = (√(1−4z²) + d)/l` —
  то же, что `alpha.py` при θ=π, δ=0).
- **Площади S** в явном виде — это закрывает часть пробела §2 (но только для θ = π).
- Критерий выбора формы: устойчива форма с минимальной S среди допустимых → основа для `--shape auto`
  / фазовой диаграммы. Проверено МД (кальцит + декан + вода, k = 0.2, 15 точек — все совпали).

Наблюдения (из разбора, требуют проверки при переносе):

- Для droplet, doughnut, perforation k входит в профиль только через `k l²` (эффективно `l_eff = l√k`),
  для worm и roll профиль от k не зависит; k отдельно нужен только в «стеночных» условиях существования.
  Обобщение на произвольные θ, δ при k ≠ 1 в статье **отсутствует** — гипотеза `l² → k l²` не проверена.
- Вероятные опечатки в статье: образующая doughnut (`d` вместо `d/2`), подпись `d_dou` в формуле roll,
  коэффициенты в границах существования perforation (ур. 23). Сверить с оригиналом PDF/авторами.

**Для архитектуры:** k — параметр `SlitPore` (по умолчанию 1), а не новый тип поры.

**Открытый вопрос:** откуда в PDF-задании треугольная и цилиндрическая поры — формул для них нет ни в коде,
ни в этой статье. Для проверки расширяемости прототипа на «второй поре» варианты:
(а) получить формулы от руководителя; (б) использовать прямоугольную ячейку (k) как вариацию геометрии;
(в) вывести простую вторую пору самим (например, цилиндрический канал с θ = π) — только как тестовый пример.
